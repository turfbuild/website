`refresh` reads every object the workspace manages and writes what it found into state. It changes
nothing in the world. Like every Turf™ run, it plans first and stops at an approval point, so you see
what state will record before it does.

## How it works

**What it runs.** `refresh` is `tofu apply -refresh-only`: one round, the same plan gate and approval
point as `up`. `plan` reads every managed object and plans writing what it found into state; `apply`
with the plan's digest writes it. There is no single-resource refresh: every object is read.

**Where drift shows.** `plan.drift` counts the objects the refresh found changed outside Terraform®,
and the plan document lists them under `resource_drift`. After the apply, `rounds[].drift` records how
many the round wrote into state.

**`refresh: false` is something else.** It is an option of a round's `plan`
(`tofu plan -refresh=false`): plan against the state as recorded, without reading the objects. It
holds for that round only.

## What a plan on an applied configuration tells you

With `refresh` on (the default), every `up` plan reads every object first. What the plan shows is the
drift report:

| Plan | Meaning | What the agent does |
|---|---|---|
| `converged` at once, nothing applied | State matches the files | Tells you "no drift". |
| `update` or `replace` | Reality diverged from the files | Presents the diff and asks whether to bring reality back to the files (apply) or the files to reality (edit them, then `up`). |
| orphan `delete` | In state, no longer in the files | Asks: restore the block, forget it with a `removed` block, or let the delete proceed. |
| `create` | In the files, not in state | Deleted out of band, or never applied: the apply creates it again. |

## Arguments

`refresh` takes the arguments every start verb takes: `workspace_alias`, `var`, `var_file`,
`overlays` and `plan_only` (see [Deploy or update with up](/docs/using/up/#arguments)). Its `plan`
takes `refresh`; `replace` is refused.
