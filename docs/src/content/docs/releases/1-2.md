Released 2026-10-28.

Turf™ 1.2 installs providers the way your team already does: from your provider mirror, your private registry or your air-gapped copy, configured once for OpenTofu™ and Turf alike. In a cluster, the engine can now run as several replicas. Modules can pass a secret to their caller without writing it to state.

1.2 is built on OpenTofu 1.12.9 and tested on restate-server 1.8.1. It is a minor release: upgrading stops any 1.1 rollout still waiting for approval, so read "Before you upgrade" first.

## What's new

**Your provider mirrors work in Turf.** If you install providers from a mirror, whether to keep an air-gapped network off the internet, to serve a private registry, or to stop CI hitting the public one, Turf now uses the same setup. It reads the `provider_installation` block of your OpenTofu CLI configuration (`~/.tofurc`, or the file `TF_CLI_CONFIG_FILE` names), as `tofu init` does. That covers filesystem, network and OCI mirrors, with their `include` and `exclude` patterns:

```hcl
provider_installation {
  network_mirror {
    url     = "https://mirror.example.com/providers/"
    include = ["registry.opentofu.org/hashicorp/*"]
  }
  direct {
    exclude = ["registry.opentofu.org/hashicorp/*"]
  }
}
```

The engine reads this file when it starts, so run `brew services restart turf` after you change it.

**Test a provider you're building.** `dev_overrides` works as it does under OpenTofu: plans run your local build of the provider, and `init` warns you which directory it came from.

**Scale the engine out.** In a Kubernetes® cluster, you can run more than one `turf-engine` replica against one restate-server, so the engine stays up when a pod goes away. Every replica installs the modules a plan used and checks them against what was planned, so an apply never runs with a different module from the one you approved. The kagent example in turfbuild/turf-examples runs two replicas.

**Ephemeral outputs from modules.** A module can now hand a secret, such as a token or a generated password, to the configuration that calls it without the value reaching state or the saved plan. Declare the output `ephemeral = true`:

```hcl
output "db_password" {
  value     = ephemeral.random_password.db.result
  ephemeral = true
}
```

The rules are OpenTofu's: the caller can use the value only where an ephemeral value is allowed (a write-only attribute, a provider block, another ephemeral output), an output that isn't declared ephemeral refuses one, and a root output can't be ephemeral.

## What's fixed

- **Provider install problems fail straight away, with OpenTofu's message.** Before, the engine kept retrying until `up` timed out. This covers a provider your mirror doesn't carry, a mirror with no package for the engine's platform (for example, a mirror filled on a Mac and served to a Linux engine), and a locked version no source offers any more.
- **A root output over `ephemeralasnull()`** planned and then failed its apply. It now applies, as in Terraform®.

## Before you upgrade

- **`TF_PROVIDER_MIRROR_DIR` is no longer read.** If you set it, move the directory into a `provider_installation` block before you upgrade, or providers come from the public registry:
  ```hcl
  provider_installation {
    filesystem_mirror {
      path = "/path/that/TF_PROVIDER_MIRROR_DIR/named"
    }
  }
  ```
- **A broken CLI configuration now stops the engine at start.** `tofu` warns and carries on instead. Turf stops because carrying on would quietly install from the public registry what you meant to take from your mirror. This covers a file that doesn't parse, a mirror without its `path`, a `TF_CLI_CONFIG_FILE` that names no file, and a `plugin_cache_dir` or `TF_PLUGIN_CACHE_DIR` naming a directory that doesn't exist. If `brew services restart turf` doesn't bring the engine up, check `~/.turf/engine/engine.log`.
- **The first plan after the upgrade fetches each module once more.**

## Upgrading from 1.1

```sh
brew upgrade turfbuild/tap/turf
brew services restart turf
```

Then restart your agent's MCP connection too, because a 1.1 server can't talk to the 1.2 engine.

1.2 runs its own engine beside 1.1's. At the restart, every rollout still on the 1.1 engine is stopped. One waiting for approval or for a turf action ends as `cancelled`, with the upgrade named as the cause, and one in the middle of an apply finishes what is in flight and ends `partial`. Everything already applied is kept: run `up` again to plan what remains. The 1.1 engine goes away as soon as nothing is left on it, usually within a minute, and `turf-mcp-server engine status` shows it while it drains.

**In a cluster**, replace every 1.1 replica before a 1.2 replica serves. All replicas need the same `--data-dir` and the same CLI configuration. Pin each module's source, a git source to a ref and a registry source to an exact version: a replica that has never seen a module fetches it at its first apply, and a source that could install differently on two replicas is refused by name until it is pinned.

## Install

```sh
brew install restatedev/tap/restate-server turfbuild/tap/turf
brew services start turf
```

Then connect your agent:

```sh
npx add-mcp@2 "$(command -v turf-mcp-server)" --name turf -g
# or, for Claude Code:  claude mcp add turf --scope user -- turf-mcp-server
```

Or use the Turf CLI with your own model API key: `turf -C ./path/to/config up`.

Each tarball carries four binaries, `turf`, `turf-mcp-server`, `turf-engine` and `turf-builtin-provider`, which go on your `PATH` side by side. Setup for each agent: https://github.com/turfbuild#connect-your-agent.

## Container image
```sh
docker pull ghcr.io/turfbuild/turf-mcp-server:v1.2.0   # also :latest
```

## Verify your download

```bash
ID='^https://github.com/turfbuild/turf-mcp-server/'
ISS=https://token.actions.githubusercontent.com

# CLI — provenance + SBOM
gh attestation verify turf --repo turfbuild/turf

# Server binary — cosign (bundle ships on this release);
# turf-engine and turf-builtin-provider verify the same way, with their own bundles
cosign verify-blob-attestation --type slsaprovenance1 \
  --bundle turf-mcp-server-<os>_<arch>.provenance.sigstore.json \
  --certificate-identity-regexp "$ID" --certificate-oidc-issuer "$ISS" \
  turf-mcp-server-<os>_<arch>

# Container image
cosign verify ghcr.io/turfbuild/turf-mcp-server:v1.2.0 \
  --certificate-identity-regexp "$ID" --certificate-oidc-issuer "$ISS"
```

`checksums.txt` is the no-tooling fallback.
