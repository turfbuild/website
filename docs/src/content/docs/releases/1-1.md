Released 2026-10-26.

Turf™ 1.1 runs more of what Terraform® and OpenTofu™ run: `lifecycle.prevent_destroy`, local modules outside the configuration directory, and `dynamic` blocks in `.tf.json`. The engine no longer writes into your configuration, so a configuration can be read-only. 1.1 is built on OpenTofu 1.12.9 and tested on restate-server 1.8.1. It is also the first minor release, and upgrading from 1.0 stops any rollout still waiting for approval. Read "Upgrading from 1.0" first.

Turf is free for noncommercial use under the PolyForm Noncommercial License 1.0.0. Commercial use, including a company's internal use, needs a license, and companies can evaluate Turf free for 60 days: https://turf.build/licensing. The `turf` CLI is open source (MPL-2.0).

## What's new in 1.1

- **`lifecycle.prevent_destroy` is honoured.** Turf 1.0 refused the block outright. 1.1 enforces it as OpenTofu 1.12 does: a plan that would delete or replace a protected object is refused, in `up` and in `destroy`, and the state is left as it was. OpenTofu's dynamic form, an expression rather than a literal, works too. `destroy = false` still overrides it.
- **Local modules can live outside the configuration directory.** `source = "../modules/network"` works, as in Terraform, so sibling roots can share their modules. Every relative path a configuration names resolves from the configuration directory, through its symlinks, as after `tofu -chdir`. `path.cwd` is that directory.
- **A configuration can be read-only.** The engine installs a workspace's modules in a data directory of its own, one per workspace, never in the configuration: `turf-engine --data-dir`, by default the per-user cache. The `turf` service uses `~/.turf/engine/data`. You can mount a configuration read-only, for example as a Kubernetes® image volume, with nothing set on the engine. Such a configuration needs remote state.
- **`dynamic` blocks in `.tf.json` configurations.**
- **`-var` and `-var-file` apply in the order given**, a later one winning, as on Terraform's command line.

## What changes when you upgrade

- **`path.module` and `path.root` are spelled as OpenTofu spells them**: relative to the root module (`.`, `modules/x`), where 1.0 printed absolute paths. In a module installed from a registry or git, `path.module` is now the engine's absolute module directory, as OpenTofu spells it under an absolute `TF_DATA_DIR`. **An attribute a workspace built from either value plans as an update on the first `up` after the upgrade**, and as a replace where the attribute forces one (`local_file.filename`, a `terraform_data` input, a `null_resource` trigger). Review that first plan before you approve it.
- **A local backend reached through a symlink** (macOS `/tmp` and `/var` included) is refused once, at its first `up`, until `open({reconfigure: true})`. The message says why.
- **`TF_DATA_DIR` in the engine's environment is ignored.** `--data-dir` is the engine's setting. The MCP server still reads `TF_DATA_DIR` for `init`'s own install, as tofu does.
- **A `lifecycle.destroy` that names a variable** reports OpenTofu's own diagnostic, "Variables not allowed", in place of "must be a boolean constant".

## What's fixed

- A refresh-only `up` that found drift on a `destroy = false` object cleared the flag, so removing the block later would have destroyed the object instead of forgetting it.
- A refresh-only apply writes the merged dependencies, as OpenTofu does.
- `prior_state` keeps a deposed object with its address.
- A failed state lock reads "locking state" once.

## Upgrading from 1.0

```sh
brew upgrade turf
brew services restart turf
```

1.1 is a minor release, so it runs its own engine beside 1.0's. At the restart, every convergence still running on the 1.0 engine is asked to stop: a rollout waiting for approval or for a turf action ends as `cancelled`, with the upgrade named as the cause. A round in the middle of an apply finishes what is in flight and ends `partial`. What was applied is kept. Run `up` again from a 1.1 client to plan what remains. The 1.0 engine retires as soon as nothing is left on it, usually within seconds. `turf-mcp-server engine status` shows it while it drains. Restart your agent's MCP connection too: a 1.0 server refuses the 1.1 engine.

Turf 1.1 is tested on restate-server 1.8.1, the version Homebrew installs. The engine warns at startup when restate-server drops signals sent before a run starts, a 1.8.1 option the `turf` service turns on. The `turf` service also refuses to start a restate-server more than one minor version away from the one that last ran its data, because restate-server upgrades its data one minor version at a time. The message names the version to run once first.

## Install

```sh
brew install restatedev/tap/restate-server turfbuild/tap/turf
brew services start turf
```

Then connect your agent:

```sh
npx add-mcp@2 "$(command -v turf-mcp-server)" --name turf -g
# or, for Claude Code:  claude mcp add turf --scope user -- turf-mcp-server
```

Or use the Turf CLI with your own model API key: `turf -C ./path/to/config up`.

Each tarball carries four binaries, `turf`, `turf-mcp-server`, `turf-engine` and `turf-builtin-provider`, which go on your `PATH` side by side. Setup for each agent: https://github.com/turfbuild#connect-your-agent.

## Container image
```sh
docker pull ghcr.io/turfbuild/turf-mcp-server:v1.1.0   # also :latest
```

## Verify your download

```bash
ID='^https://github.com/turfbuild/turf-mcp-server/'
ISS=https://token.actions.githubusercontent.com

# CLI — provenance + SBOM
gh attestation verify turf --repo turfbuild/turf

# Server binary — cosign (bundle ships on this release);
# turf-engine and turf-builtin-provider verify the same way, with their own bundles
cosign verify-blob-attestation --type slsaprovenance1 \
  --bundle turf-mcp-server-<os>_<arch>.provenance.sigstore.json \
  --certificate-identity-regexp "$ID" --certificate-oidc-issuer "$ISS" \
  turf-mcp-server-<os>_<arch>

# Container image
cosign verify ghcr.io/turfbuild/turf-mcp-server:v1.1.0 \
  --certificate-identity-regexp "$ID" --certificate-oidc-issuer "$ISS"
```

`checksums.txt` is the no-tooling fallback.
