Released 2026-11-27.

Turf™ 1.5 is available now. From this release Turf ships under a new license, the Turf Community Edition License 1.0, and asks you to accept it once. It also watches between runs: turn drift detection on for a workspace, and the engine finds what changed outside Turf and tells your agent what the change means. And it installs with one command: the MCP server is an npm package, and it starts the engine when a tool first needs it.

1.5 is built on OpenTofu® 1.12.9 and tested on restate-server 1.8.1. It is a minor release: nothing runs until you accept the license terms, and upgrading restarts the engine and stops any 1.4 rollout still waiting for approval, so read "Before you upgrade" first.

## The Turf Community Edition License

**Who uses Turf free.** Turf is free for individuals, education, non-commercial open source projects and small businesses, within the Community limits. Government and larger organizations need a commercial license. Who that covers, and the limits themselves, are in plain words at https://turf.build/licensing/; the binding text is at https://turf.build/license/v1/.

**Evaluate without signing anything.** Any organization, government included, can evaluate Turf in non-production for 30 days from its first use. The free 60-day pilot on the Common Paper Pilot Agreement stays, for a longer or supported trial.

**The same binary, and no license key.** Every build is the same binary with the same features. There is no license key, no license server and no update check. The `turf` CLI's source stays open under MPL-2.0.

**Accepted once, by you.** The terms are a public cover page on the Common Paper Software License Agreement Standard Terms 1.1, and each release names the version of the terms that governs it. You accept them by an act of your own:

- run `turf license accept`, which records the acceptance in `~/.turf/license.json` (without the `turf` CLI, `npx -y @turfbuild/turf-mcp-server license accept` records the same);
- or type `yes` when the `turf` CLI asks, on its first run in a terminal;
- or set `TURF_ACCEPT_EULA=yes` where no one is there to answer: a container, a CI job, a Kubernetes® pod, an MCP client's configuration. Setting it accepts the terms at https://turf.build/license/v1/.

Every release archive carries the terms as `LICENSE`, the standard terms as `STANDARD-TERMS.md` and the third-party notices as `NOTICE`. `turf --version` prints the license in two lines.

**Telemetry.** With telemetry on, the engine's `engine.start` event gains two fields: `terms_version` and `terms_accepted_via`. Nothing else about your acceptance is sent, and nothing at all with telemetry off. The field list is at https://turf.build/telemetry/.

Releases 1.0 to 1.4 keep the license they shipped with.

## What's new

**Drift detection between runs.** Terraform® and OpenTofu look at the world only when someone runs a plan. Turf can now watch in between. Turn drift detection on for a workspace, and when an object it manages changes outside Turf, the engine finds it on its next sweep, works out what the change means for your configuration, and tells your agent. The agent gets a **drift notice** for each address: a class, the attribute paths that changed, what saw it and when. Paths, never values. What happens next is an ordinary run, with a plan, an approval point and an apply. Nothing applies on its own.

It is off until you turn it on, and turning it on or off is your choice: the agent calls `drift` only on your words.

```
drift({ workspace_alias, enabled: true, sweep: 86400 })   → detection on, one sweep a day
watch({ workspace_alias })                                → returns when something new drifts
up, then plan({ convergence_id, refresh_drift: true })    → a plan that reads only what drifted
```

**The sweep finds the change.** The engine reads every managed object on a paced cycle you choose (once a day is the usual cadence), against the provider's API with the engine's credentials. It works with any provider, and it needs nothing installed beside the engine. `status` and the console count what it covers: swept, or not read until the next run. A sensor for Kubernetes that reports a change as it happens is coming soon.

**Notices that say what a change means.** The engine classifies each read before it reaches the agent:

- `gone`: the object is missing.
- `configured`: a setting your configuration makes was changed.
- `referenced`: a computed value some expression reads has changed, so its dependents will plan.
- `contended`: the same paths drifted again after two runs put them back. Another controller owns them, and the notice says to use `ignore_changes` or stop the other controller instead of running `up` a third time.

Noise never becomes a notice: a computed attribute nothing reads, a path under `ignore_changes`, a status-only update, Turf's own writes during a run.

**`watch`: the agent waits for drift.** `watch` returns when there is something new to act on and says nothing while there is not. It only observes. On a workspace nothing watches it returns at once and says why: no state yet, detection never turned on, or turned off and when. The `/turf:watch` prompt runs the whole loop: wait, show the notices, run the `up`, review the plan with you, watch again.

**A plan that reads only what drifted.** At the plan gate of any `up`, `plan` with `refresh_drift: true` reads the objects the open notices name and plans every other row from its record. On a large workspace that is the difference between reading everything and reading one object. A row that then plans a change is read again first, so nothing is applied over a stale record, and the result says how many rows were planned unread. The run that puts drift back is an ordinary `up`: nothing marks it, and the engine records which run cleared each notice.

**Detection from the first deploy.** A new workspace has no state for detection to watch yet. Pass the settings to the first `up` as `drift: { sweep: 86400 }`, and detection turns on when that run converges. Every result of the run says where the ask stands. If you turn detection off before the run finishes, that later choice wins.

**The Drift tab in the console.** A workspace's Drift tab shows it between runs: the open notices, how much is swept or uncovered, and whether the sweep is keeping to its cycle. The Runs tab shows on each run how many drift notices it cleared. The console stays read-only: detection is turned on and off, and its settings changed, with the `drift` tool.

**One command to install, and the engine starts on demand.** The MCP server is now an npm package, `@turfbuild/turf-mcp-server`, for macOS and Linux on arm64 and x64, with Node 18 or later. `npx add-mcp@2 @turfbuild/turf-mcp-server --name turf -g` adds it to the agents on your machine, and npm brings the server, the engine and the console. The server starts the engine the first time a tool needs it, so there is no service to start first. The engine keeps running when your agent quits, so a rollout waiting for your approval is still there next time. `turf-mcp-server engine stop` stops it, and the next call starts it again. The Homebrew service is optional: `brew services start turf` starts the same engine at login and takes over one a server started. More in [Install](/docs/start/install/) and [The engine and the console](/docs/concepts/engine-and-console/).

**Faster plans on large configurations.** A plan no longer waits on each row's evaluation before it dispatches the next. In our measurements at 1,000 objects, a create plan went from about 50 seconds to 13, and a destroy plan from about 154 seconds to 13.

**The console shows when a round waits on you.** The plan gate is drawn as a wait on a person, in amber, as the approval point and an unanswered turf action are, and a round's plan time now starts when its plan gate is answered instead of counting the wait. Work in progress is drawn as a pale tint that fills solid when it lands, and planning has its own color.

**Tool titles and hints.** Every tool carries a title and the MCP hints that say whether it only reads and whether it can remove or overwrite something. A client that shows titles shows `apply` as "Approve and apply plan"; one that lets read-only tools run without asking can do that for `status`, `show`, `list`, `output`, `state_list`, `provider_search`, `watch` and the skill readers.

**HTTPS for the HTTP endpoint.** `turf-mcp-server --transport http` serves HTTPS itself with `--tls-cert` and `--tls-key` (or `TURF_TLS_CERT` and `TURF_TLS_KEY`), so a `TURF_MCP_AUTH_TOKEN` no longer crosses the network in cleartext when no proxy sits in front. It takes TLS 1.2 or later, and picks up a renewed certificate when its files change, as a mounted Kubernetes secret does.

**One switch for an air gap.** With `TURF_OFFLINE=1`, Turf makes no call of its own to the internet: the engine's telemetry is off, `provider_search` answers with what to do instead of calling the public registry (`TURF_REGISTRY_API_URL` points it at a registry API inside your network), and the `turf` CLI's model catalog comes from the copy built into the binary. More in [Air-gapped installation](/docs/security/air-gapped/).

## Variables from your agent reach providers

**Name it in the entry.** A provider that needs a variable, such as `AWS_PROFILE` or `KUBECONFIG`, now gets it from your agent's entry for Turf. Put the variable in the entry's `env` and name it in `TURF_PROVIDER_ENV`, then restart the agent:

```json
"env": {
  "AWS_PROFILE": "prod",
  "TURF_PROVIDER_ENV": "AWS_PROFILE"
}
```

The server sends the variables you named to the engine with each run. Nothing is sent unless you name it, and `PATH` and the engine's own variables are never sent. Credentials in their usual files still work with nothing set.

**No more `turf.env` for a provider's variable.** A provider's variable no longer needs a line in `~/.homebrew/services/turf.env` and a restart of the Homebrew service. That file is for what the engine itself needs, such as a proxy.

**Visible by name only.** `status` lists the names a run would send, and every result of a run lists the names it sent. No tool, log or error shows a value.

**Planfiles and drift checks.** A saved plan applied later runs with the values of the server that applies it, not the planner's. A drift check that runs with nobody attached reads with the values of the last `up` that converged: after you rotate a credential, the next `up` that converges hands those reads the new value.

More in [Send a variable to providers](/docs/environment/provider-environment/).

## What's fixed

- **A resource that reads a value from an unchanged resource is applied with the value the plan showed.** When a refresh found that value changed, the plan showed the new one and the apply wrote the old one, with no error. This happened under an ordinary full refresh in 1.4.
- **The apply holds providers to their plans, as OpenTofu does.** A create or update whose provider plans differently at apply time fails with "provider produced inconsistent final plan", before anything is applied. One whose result contradicts its plan is committed and fails with "provider produced inconsistent result after apply". A provider on the legacy SDK is tolerated, as OpenTofu tolerates it.
- **A planfile's apply no longer leaves its provider plugins running** until the engine stops.
- **Security updates.** Go 1.26.11 and dependency updates clear the advisories the release's scans reported, and the release's SBOM is scanned before it is attested.

## Before you upgrade

- **1.5 does nothing until the license terms are accepted.** Read them at https://turf.build/license/v1/ before you upgrade.
- **Check whether your use is free under the new terms**: https://turf.build/licensing/. From 1.5 a small business uses Turf free within the Community limits, and government needs a commercial license.
- **In a cluster, acceptance is an `env` entry in each Turf container**: the engine, the server and the console. Add it to your manifests before 1.5 rolls out ([Minimal manifests](/docs/cluster/manifests/#the-license)). The image does not set it for you.
- **A CI job that runs `turf` needs `TURF_ACCEPT_EULA=yes` in its environment**, or it exits with status 77. Setting it accepts the terms at https://turf.build/license/v1/.
- **Drift detection is off on every workspace after the upgrade**, and stays off until you turn it on.
- **The sweep reads unattended.** It runs with the engine's credentials against your provider's API, and with any provider environment the last converged `up` sent (`TURF_PROVIDER_ENV`), with nobody at an approval point. It only reads. Pick its cycle with your API limits in mind: one cycle a day is the usual cadence.
- **The engine keeps what it needs to read between runs.** After every `up` that converges, the engine keeps that run's configuration and variable values, sensitive ones included, in its own store, until the next converged `up` replaces them or a converged `destroy` removes them. Ephemeral variables are never kept, so a provider configured from one is not read between runs.
- **What drift detection does not see:** objects Turf does not manage, data sources, and objects inside a Helm® release (the release is read as one object).
- **The Turf CLI and `turf-mcp-server` must be the same release**, as before.

## Upgrading from 1.4

```
brew upgrade turfbuild/tap/turf
brew services restart turf
turf license accept
```

Then restart your agent's MCP connection too, because a 1.4 server can't talk to the 1.5 engine.

Until you run `turf license accept`, this is what a 1.4 user sees after the upgrade:

- **The engine service is up and has started nothing.** `turf-mcp-server engine status` says `awaiting license`. The service checks every 2 seconds and starts the engine within seconds of your acceptance, with no second restart.
- **Your agent's calls return the license notice.** The MCP server starts and lists its tools, and every tool call returns the notice with a note asking the agent to have you read the terms and confirm. After `turf license accept` the next call runs; the server needs no restart.
- **The `turf` CLI asks.** On a terminal it prints the notice and waits for `yes`. With no terminal, as in CI, it prints the notice and exits with status 77.
- **In a cluster, the engine and the console exit with status 77**, and their pods go to `CrashLoopBackOff` until the `env` entry is there. The server starts, and every call returns the notice.

A variable set in your shell or in an MCP client's configuration does not reach the Homebrew service. The record `turf license accept` writes does, and so does `~/.homebrew/services/turf.env`. Each case is in [Accept the license](/docs/start/install/#accept-the-license).

1.5 runs its own engine beside 1.4's. When it starts, every rollout still on the 1.4 engine is stopped. One waiting for approval or for a turf action ends as `cancelled`, with the upgrade named as the cause, and one in the middle of an apply finishes what is in flight and ends `partial`. Everything already applied is kept: run `up` again, and `plan` plans what remains. The 1.4 engine goes away as soon as nothing is left on it, usually within a minute, and `turf-mcp-server engine status` shows it while it drains.

**In a cluster**, add the `env` entry to the engine, server and console containers, then replace every 1.4 replica before a 1.5 replica serves ([Upgrading in a cluster](/docs/cluster/upgrading/#upgrading-to-15)).

## Install

```
npx add-mcp@2 @turfbuild/turf-mcp-server --name turf -g
# the first start downloads Turf: about a minute
```

One command installs Turf and connects your agent. It needs Node 18 or later, on macOS or Linux, arm64 or x64. npm brings the server and its engine, and the engine starts when a tool first needs it. Read the terms at https://turf.build/license/v1/, then accept them once:

```
npx -y @turfbuild/turf-mcp-server license accept
```

Or install with Homebrew, which adds the `turf` CLI and an engine that starts at login. `turf license accept` accepts the same terms:

```
brew install restatedev/tap/restate-server turfbuild/tap/turf
turf license accept
npx add-mcp@2 "$(command -v turf-mcp-server)" --name turf -g
brew services start turf        # optional: the engine at every login
```

With Homebrew you can also use the Turf CLI, with your own model API key: `turf -C ./path/to/config up`.

Each tarball carries five binaries, `turf`, `turf-mcp-server`, `turf-engine`, `turf-builtin-provider` and `turf-ui`, which go on your `PATH` side by side. The npm package carries the last four; no npm package carries the `turf` CLI. Setup for each agent: [Connect your agent](/docs/start/connect/).

## Container image
```
docker pull ghcr.io/turfbuild/turf-mcp-server:v1.5.0   # also :latest
```

Set `TURF_ACCEPT_EULA=yes` in each container's environment to accept the terms at https://turf.build/license/v1/.

## Verify your download

```bash
ID='^https://github.com/turfbuild/turf-mcp-server/'
ISS=https://token.actions.githubusercontent.com

# CLI — provenance + SBOM
gh attestation verify turf --repo turfbuild/turf

# Server binary — cosign (bundle ships on this release);
# turf-engine, turf-builtin-provider and turf-ui verify the same way, with their own bundles
cosign verify-blob-attestation --type slsaprovenance1 \
  --bundle turf-mcp-server-<os>_<arch>.provenance.sigstore.json \
  --certificate-identity-regexp "$ID" --certificate-oidc-issuer "$ISS" \
  turf-mcp-server-<os>_<arch>

# Container image
cosign verify ghcr.io/turfbuild/turf-mcp-server:v1.5.0 \
  --certificate-identity-regexp "$ID" --certificate-oidc-issuer "$ISS"
```

`checksums.txt` is the no-tooling fallback. More in [Verify a release](/docs/security/verify-releases/).
