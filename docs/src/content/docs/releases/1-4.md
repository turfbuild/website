Released 2026-11-08.

Turf™ 1.4 ships the console: a read-only web view of every workspace's runs, rounds and approvals, running beside the engine. Every result the MCP server hands an agent now carries a link into it, so when the agent says "the plan is ready", there is a page to look at: the round, its plan, who approved what and when, and every resource's lane as the apply runs.

1.4 is built on OpenTofu™ 1.12.9 and tested on restate-server 1.8.1. It is a minor release: upgrading restarts the engine and stops any 1.3 rollout still waiting for approval, so read "Before you upgrade" first.

## What's new

**The console.** `brew services restart turf`, then `turf console`, which signs your browser in and opens `http://127.0.0.1:8873`. A workspace opens on its runs, newest first, each opened into its rounds: what each round is doing or how it ended, the plan's size, its approval point and who gave it, how long it took. A round's page tells its story from the engine's own stamps: the plan gate while it is open, the plan with its counts by action, the approval point with the approver and the plan's digest, the apply, any turf action the apply is asking, and how the round ended the run. The Timeline tab draws every resource's lane as the apply runs, live; Plan and Graph show one round's plan and configuration graph; State shows what the workspace holds, its outputs and every address, each opening to its committed record.

It is read-only: approvals are given where they always were, by the agent or the CLI. And only you can open it: the console asks for a token only your account can read, `turf console` signs a browser in once, and every link opens directly after that (`turf console <link>` lands on the page an agent linked to; `turf console --print` prints the sign-in link for an `ssh -L` tunnel).

**A link in every result.** Every `up`, `plan`, `apply`, `status` and `open` result carries `console_url`, the page for the round it is about, and the result's note asks the agent to give you that link. `turf up` in the terminal shows it beside each gate. Set `TURF_CONSOLE_ADDR` to move the console (`off` turns it off), or `TURF_CONSOLE_URL` on a server whose console lives elsewhere, such as a cluster.

**The console in a cluster.** `turf-ui` ships in the `turf-mcp-server` image. Off loopback it takes a token (`TURF_CONSOLE_AUTH_TOKEN`): a browser signs in once at `/login?token=…` and keeps a cookie, a program sends it as a bearer header, and nothing else is answered. The kagent example in turfbuild/turf-kagent runs it behind a port-forward, and the agent's message above an approval card links to the plan the card is about.

**Planfiles and approvers in the history.** A workspace's planfiles, and each round's approver and plan digest, are kept with the round history, so the console (and `status`) can say who approved a round after its run's own record has expired.

## What's fixed

- **`up` over a directory with no configuration files is refused**, as OpenTofu refuses it, instead of planning to destroy everything the workspace holds. `destroy` still works on an empty directory.
- **A failed apply records what the refresh read for every resource it never reached.** An update, replace or delete cancelled behind a failure used to keep its old recorded value; now the state matches what OpenTofu writes after the same failure, so the next plan starts from what is really there.
- **Sensitive values stay marked in a destroy plan and for resources removed from the configuration.** The rendered plan always hid them; the values the engine kept for those rows now carry the marks too.

## Before you upgrade

- **The console takes port 8873 on the laptop.** The Homebrew service starts it beside the engine; `TURF_CONSOLE_ADDR=127.0.0.1:<port>` in `turf.env` moves it, `TURF_CONSOLE_ADDR=off` leaves it out. The engine does not depend on it: if the console stops, the engine goes on.
- **The Turf CLI and `turf-mcp-server` must be the same release**, as in 1.3.

## Upgrading from 1.3

```
brew upgrade turfbuild/tap/turf
brew services restart turf
turf console
```

Then restart your agent's MCP connection too, because a 1.3 server can't talk to the 1.4 engine.

1.4 runs its own engine beside 1.3's. At the restart, every rollout still on the 1.3 engine is stopped. One waiting for approval or for a turf action ends as `cancelled`, with the upgrade named as the cause, and one in the middle of an apply finishes what is in flight and ends `partial`. Everything already applied is kept: run `up` again, and `plan` plans what remains. The 1.3 engine goes away as soon as nothing is left on it, usually within a minute, and `turf-mcp-server engine status` shows it while it drains.

**In a cluster**, replace every 1.3 replica before a 1.4 replica serves, and add the console's Deployment and its token Secret (the turf-kagent manifests show both).

## Install

```
brew install restatedev/tap/restate-server turfbuild/tap/turf
brew services start turf
```

Then connect your agent:

```
npx add-mcp@2 "$(command -v turf-mcp-server)" --name turf -g
# or, for Claude Code:  claude mcp add turf --scope user -- turf-mcp-server
```

Or use the Turf CLI with your own model API key: `turf -C ./path/to/config up`.

Each tarball carries five binaries, `turf`, `turf-mcp-server`, `turf-engine`, `turf-builtin-provider` and `turf-ui`, which go on your `PATH` side by side. Setup for each agent: https://github.com/turfbuild#connect-your-agent.

## Container image
```
docker pull ghcr.io/turfbuild/turf-mcp-server:v1.4.0   # also :latest
```

## Verify your download

```bash
ID='^https://github.com/turfbuild/turf-mcp-server/'
ISS=https://token.actions.githubusercontent.com

# CLI — provenance + SBOM
gh attestation verify turf --repo turfbuild/turf

# Server binary — cosign (bundle ships on this release);
# turf-engine, turf-builtin-provider and turf-ui verify the same way, with their own bundles
cosign verify-blob-attestation --type slsaprovenance1 \
  --bundle turf-mcp-server-<os>_<arch>.provenance.sigstore.json \
  --certificate-identity-regexp "$ID" --certificate-oidc-issuer "$ISS" \
  turf-mcp-server-<os>_<arch>

# Container image
cosign verify ghcr.io/turfbuild/turf-mcp-server:v1.4.0 \
  --certificate-identity-regexp "$ID" --certificate-oidc-issuer "$ISS"
```

`checksums.txt` is the no-tooling fallback.
