Every round has an approval point, and `apply` with the plan's digest is the approval, of that plan and
no other. Nothing runs off-plan. The question is who says yes, and Turf™ answers it with a rule the
server hands every agent.

## Who approves

**The agent approves a low-risk plan itself.** Low-risk means all of: creates and in-place updates
only; no replace; no delete of anything holding data or state; no IAM or network-exposure change; no
warning the agent cannot explain; and you have not asked to be consulted. The last plan of the first run, a
single create, is the shape of it. The agent still tells you what it approved.

**Everything else comes to you.** The agent presents the plan (the counts, each address with its
before and after, every action the round will run, what is deferred) and asks: "Ready to apply these
changes?" It waits for an explicit yes. A "no" is `apply` with `decline`: nothing is applied, the run
ends `declined`, and the workspace is free.

**A destroy always comes to you.** The agent never approves a destroy plan. It asks: "Ready to destroy
these resources? This cannot be undone." In a destroy, a failing turf action is only a warning and the
teardown goes on, so your yes at this point is the guard.

**A delete of something that holds data** (a database, a bucket, a volume, a cluster) is your call in
any round. The agent asks before removing its block or running `destroy`, and offers a backup first, or
to stop managing the object and leave it running (a `removed` block with `destroy = false`).

**The CLI's `--yes`** approves every round without asking. It is for scripted runs whose plans you
already trust; the turf-examples recordings never use it for a plan a viewer should read.

Every round is its own decision. Approving round 1 says nothing about round 2.

## What the approval records

`rounds[].approval` in every result says how each round's plan was applied: `asked` (someone approved
it), `unneeded` (nothing to consent to) or `planfile` (applied from a sealed plan). The console keeps each round's approver and the plan's digest with the round history, so you can see who
approved what after the run's own record has expired. The approval is of a digest, so a plan that
changed cannot be applied with an old yes: if the configuration changes between `plan` and `apply`,
the run ends `stale` and nothing is applied.

## Checks before the yes

**A policy check on the plan.** The plan is OpenTofu's json-format plan, exactly as `tofu show -json`
prints it, with sensitive values redacted. The agent reads it with `show` and hands it to your policy
tool (OPA or conftest, Checkov) as `input.tfplan`. A deny means do not apply. The Scalr example in
turf-examples runs an OPA policy group this way. [Policy checks on a plan](/docs/using/policy/).

**A check on the providers before the first plan.** `init` reports every provider the lock file
records, with its version, its hash and its package directory. A vulnerability scanner or a policy tool
checks those against a CVE database before anything runs; the [guardrails example](https://github.com/turfbuild/turf-examples/blob/130fcb754897c36de2fd25062495ee47011c9ab0/use-cases/guardrails) in turf-examples does
exactly that. The agent's skill tells it to scan `providers[]` if it has a scanner. An unwanted provider
version is caught before the first `up`, not after.

**The plan itself.** The agent calls out every replace and delete, above all of anything that holds
data (a replace deletes the old object); IAM and network-exposure changes; every action the round
runs; deferrals; imports that replace an object; and any warning it cannot explain. It never shows a
sensitive value, only that one changes.

## The approval in the result

```text
plan({ convergence_id })
→ outcome: awaiting_approval, plan: { uri, digest, add, change, destroy, replace, … }, console_url
apply({ convergence_id, plan_digest })            # the approval
apply({ convergence_id, decline: true, reason })  # the refusal
```

A digest approves only the plan it names. If the run has moved on to another plan, nothing is applied
and the result says which plan it holds. The agent never resends an old digest; it reads the new plan
and decides again.
