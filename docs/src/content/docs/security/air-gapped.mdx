Turf™ is self-hosted: the server, the engine and the console run on your machines, and your state,
plans and credentials stay there. This page shows how to run it where nothing can reach the internet.

There is no license server and no update check. What Turf fetches is the software itself, the
providers and modules your configurations name, and, unless you turn them off, usage telemetry and a
few lookups. Each has an answer below.

## The switch

Set `TURF_OFFLINE=1` and Turf makes no call of its own to the internet:

| Component | With `TURF_OFFLINE=1` |
|---|---|
| The engine | Usage telemetry is off. |
| The MCP server | `provider_search` does not call the public registry. It answers with what to do instead. |
| The `turf` CLI | The model catalog comes from the copy built into the binary, never from models.dev. |

Set it wherever each process starts: in `turf.env` for the Homebrew service, in your agent's server
definition for the MCP server, in the pod's environment in a cluster, and in your shell for the CLI.

The switch does not change where providers and modules come from. That is your configuration's
business, covered in [Providers](#providers) and [Modules](#modules).

## The release

On a connected machine, download the archive for your platform and `checksums.txt` from the
[release](https://github.com/turfbuild/turf/releases), and
[verify them](/docs/security/verify-releases/) there. Download restate-server, the engine's
dependency, from [Restate's releases](https://github.com/restatedev/restate/releases); Turf does not
redistribute it.

Inside the network, either unpack the archive yourself or point the install script at a mirror.

```sh title="By hand"
mkdir -p ~/.turf/bin
tar -xzf turf_v1.4.0_linux_amd64.tar.gz -C ~/.turf/bin
tar -xJf restate-server-x86_64-unknown-linux-musl.tar.xz --strip-components 1 \
  -C ~/.turf/bin restate-server-x86_64-unknown-linux-musl/restate-server
export PATH="$HOME/.turf/bin:$PATH"
TURF_OFFLINE=1 turf-mcp-server engine run
```

```sh title="With the install script, from a mirror"
export TURF_DOWNLOAD_URL=https://mirror.example.com/turf/releases
export TURF_RESTATE_DOWNLOAD_URL=https://mirror.example.com/restate/releases
sh install.sh --version v1.4.0 --no-telemetry
```

A mirror keeps the path GitHub uses: `<mirror>/download/<tag>/<file>`. The script checks both
downloads against their SHA-256 before it installs anything.

## Images

For a [cluster](/docs/cluster/images/), copy the images into your registry. `cosign copy` carries
each image's signature and attestations with it, so you can verify again on the inside:

```sh
cosign copy ghcr.io/turfbuild/turf-mcp-server:v1.4.0 registry.example.com/turf/turf-mcp-server:v1.4.0
cosign copy docker.io/restatedev/restate:1.8.1 registry.example.com/restate/restate:1.8.1
```

A configuration image is copied the same way. In the manifests, set `TURF_OFFLINE=1` on the server
and the engine, and `RESTATE_DISABLE_TELEMETRY=true` on restate-server.

## Providers

Providers install from a mirror you name in the OpenTofu® CLI configuration, with a
`provider_installation` block. Fill the mirror on a connected machine, from the configuration's
directory:

```sh
tofu providers mirror -platform=linux_amd64 /srv/providers
```

Then point both the server and the engine at it:

```hcl title="~/.tofurc"
provider_installation {
  filesystem_mirror {
    path = "/srv/providers"
  }
}
```

With no `direct` block, nothing is fetched from a public registry. A network mirror and an OCI mirror
work the same way; see
[State backend, registries and mirrors](/docs/environment/registries-and-mirrors/#provider-mirrors).

`provider_describe` installs through the same block, so it works from the mirror. `provider_search`
needs a registry's search service: under `TURF_OFFLINE` it is off, unless `TURF_REGISTRY_API_URL`
names one inside your network.

## Modules

Modules have no mirror setting. A module source must be reachable from the server and the engine:
a path in the configuration, a git host inside your network, or a private registry
([tokens](/docs/environment/registries-and-mirrors/#registry-and-remote-backend-tokens)).
Rewrite a public registry source to one of those before the configuration crosses over.

## The model

Turf does not call a model. Your agent does, and its endpoint is the agent's setting. If you use
Turf's own agent, the `turf` CLI, give it a model inside your network: a
[local model](/docs/cli/models/#run-a-model-locally), or a gateway named with `--base-url` or a
`providers` entry in `turf.yaml` ([Model providers](/docs/cli/models/)).

## What Turf contacts

Every host a default installation can reach, and what stops it:

| Host | Who calls it | For | Without it |
|---|---|---|---|
| `get.turf.build`, `turf.build` | you | The install script | Carry the script in |
| `github.com` | the install script, Homebrew | The release, restate-server | `TURF_DOWNLOAD_URL`, `TURF_RESTATE_DOWNLOAD_URL`, or unpack by hand |
| `ghcr.io`, `docker.io` | your cluster | The images | Your registry |
| `registry.opentofu.org` and each provider's download host | the server, the engine | Providers, registry modules | A `provider_installation` mirror; internal module sources |
| `api.opentofu.org` | the server | `provider_search` | `TURF_OFFLINE`, or `TURF_REGISTRY_API_URL` |
| `telemetry.turf.build` | the engine | [Usage telemetry](https://turf.build/telemetry/) | `TURF_OFFLINE`, `turf telemetry off`, `TURF_TELEMETRY=off` or `DO_NOT_TRACK=1` |
| `models.dev` | the `turf` CLI | The model catalog | `TURF_OFFLINE` |
| Your model provider | the `turf` CLI | The model | A local model or your gateway |

Everything else Turf reaches is yours: the state backend, the hosts your module sources name, and the
APIs your providers manage. Providers are separate programs, and they call what their resources need.

The console serves its own pages and loads nothing from outside.

## Data at rest

The engine keeps each run's record in restate-server's store: plans, the values of variables, and the
journal that lets a run resume. Sensitive values in that record are not separately encrypted, so put
the store on an encrypted volume and limit who can read it. State files are covered by
[state encryption](/docs/environment/state-encryption/).
